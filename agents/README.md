# agents/ 目录：私有上下文约定

每个 agent/角色一个子目录，比如 `agents\<角色名>\`，里面放这个角色自己的 `private.md`。

## 规则

- **私有文件默认只服务这个角色自己**，别的 agent 不会主动去读它——这是跟 `super_brain` 根目录那些共享偏好文件（所有 agent 都该知道）最核心的区别。
- 私有文件放什么：这个角色当前在跟的具体任务、只对它有意义的上下文细节、不需要团队其他人知道的工作笔记。
- 如果私有文件里沉淀出了一条"其他 agent 也该知道"的东西，就把它提炼后挪到 `super_brain` 根目录的共享偏好文件里（或者新建一条），不要指望别人会主动来读你的私有文件。
- 角色之间需要互相知会/请求协作，走上一级的 `inbox.md`，不要指望对方会主动翻你的私有目录。

## private.md 的格式（软约束，程序不校验，纯粹方便人和 LLM 读）

`dispatcher.py` 把这个文件整篇当纯文本读进去喂给 LLM，**不解析内部结构**，所以格式不是硬性要求。
但为了可读性一致，建议都按这个结构写：

```
# <角色名> agent

## 角色
（这个 agent 是干什么的，一两句话）

## 只属于这个角色的上下文
（专属知识/约定，别的 agent 不需要知道的细节）
```

## 决策圆桌专家（A 类）的 private.md 有额外要求

`strategy` 这类"决策圆桌专家"角色，private.md 里除了角色定位，还要有一份**结构化知识框架**——
用"条件 → 结论"的规则格式（如"若 A 且 B，则 C"），每条标注来源（书籍/理论体系），不能是
不挂钩任何依据的泛泛而谈。system prompt 要求专家输出时标注"依据第几条规则"，覆盖不到的问题
要明说"现有框架未覆盖、这是推测"。

**这类知识框架是活文档，不是一次性定稿**——写完第一版之后，会根据实际讨论效果持续修订、
补充规则、调整措辞，不要求也不可能一步到位写完美。
