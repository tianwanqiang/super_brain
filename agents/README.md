# agents/ 目录：私有上下文约定

每个 agent/角色一个子目录，比如 `agents\<角色名>\`，里面放这个角色自己的 `private.md`。

**"合法 agent 有哪些"以 `../agents.yaml` 为准，不是这个目录里有什么文件夹就算数**——
目录只是存放 `private.md` 的地方，必须在 `agents.yaml` 里正式登记过（name/type/description/
knowledge_path），`dispatcher.py` 才会认。新建一个角色，两步都要做：建目录 + 写 `private.md`，
同时在 `agents.yaml` 里加一条记录。

## 规则

- **私有文件默认只服务这个角色自己**，别的 agent 不会主动去读它——这是跟 `super_brain` 根目录那些共享偏好文件（所有 agent 都该知道）最核心的区别。
- 私有文件放什么：这个角色当前在跟的具体任务、只对它有意义的上下文细节、不需要团队其他人知道的工作笔记。
- 如果私有文件里沉淀出了一条"其他 agent 也该知道"的东西，就把它提炼后挪到 `super_brain` 根目录的共享偏好文件里（或者新建一条），不要指望别人会主动来读你的私有文件。
- 角色之间需要互相知会/请求协作，走上一级的 `inbox.md`，不要指望对方会主动翻你的私有目录。

## private.md 的格式（软约束，程序不校验，纯粹方便人和 LLM 读）

`dispatcher.py` 把这个文件整篇当纯文本读进去喂给 LLM，**不解析内部结构**，所以格式不是硬性要求。
但为了可读性一致，建议都按这个结构写：

```
# <角色名> agent

## 角色
（这个 agent 是干什么的，一两句话）

## 只属于这个角色的上下文
（专属知识/约定，别的 agent 不需要知道的细节）
```

## 决策圆桌专家（A 类）的 private.md 有额外要求

`strategy` 这类"决策圆桌专家"角色，private.md 里除了角色定位，还要有一份**结构化知识框架**——
用"条件 → 结论"的规则格式（如"若 A 且 B，则 C"），每条标注来源（书籍/理论体系），不能是
不挂钩任何依据的泛泛而谈。system prompt 要求专家输出时标注"依据第几条规则"，覆盖不到的问题
要明说"现有框架未覆盖、这是推测"。

**这类知识框架是活文档，不是一次性定稿**——写完第一版之后，会根据实际讨论效果持续修订、
补充规则、调整措辞，不要求也不可能一步到位写完美。

## 现状

已有角色：
- `ship`（专精执行型，对应 ship skill）
- `coordinator`（协调型，对应主力对话线）
- `strategy`（A 类，博弈论 + 竞争战略 + 孙子兵法）
- `finance`（A 类，单位经济学 + 现金流管理 + 经济学基础）
- `marketing`（A 类，定位理论 + 传播机制 + 消费者心理；只产出策略判断，不负责执行/发布）
- `legal`（A 类，一人公司常见合规风险；只做风险提示，不做正式法律结论，具体问题要求
  咨询执业律师/税务师）
- `toutiao`（专精执行型，生成头条号草稿，委托 `G:\code\toutiao-agent` 的逻辑，不涉及登录/发布）
- `writer`（专精执行型，把圆桌讨论原始记录写成正式会议纪要 `{date_time}_{title}.md`，
  对话内 @ 触发，不经过 inbox；输出目录是持久化设置，第一次调用时问用户、存进
  `config.json` 的 `MEETING_MINUTES_DIR`，之后不再重复问）
- `ops-assistant`（专精执行型，读取当天 `opc_{日期}.md` + `writer` 产出的会议纪要目录，
  分发到头条+公众号生成待审阅草稿，默认两个平台都发；不自动群发/发布，不做内容策略
  判断——那是 `marketing` 的事）

A 类四个专家 2026-08-14 起草，均为暂定版本，待验证效果后迭代。B 类（学习方法论/教练）
还没建，等用户明确要求再建，不预先臆造。

**`toutiao` / `ops-assistant` 是工具类助手，`writer`/`ship`/`coordinator` 是对话内角色，
和 `strategy` 这类圆桌讨论专家不是一回事——工具类助手的动作是确定性的、机械的，
`dispatcher.py` 直接调用 `publishers.py` 里的函数落地（`executor` 字段），不套 inbox
异步留言协议；圆桌讨论专家的价值恰恰来自"真正独立的推理过程"，不能简化成函数调用，
否则会丢掉独立视角之间真实交叉校验的核心价值，因此 `roundtable` 类型的 agent 不应该
注册 `executor` 字段。**

**注意**：`ops-assistant` 现在还不能无人值守自动跑——被唤起时靠当前有真实工具权限的
Claude Code 会话执行，跟 `ship` 的运作方式一样。真正的自动触发是另一个更大、被明确搁置
的问题。
